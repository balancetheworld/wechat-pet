# 宠物问问 Agent 重构规划（v1 → v2）

> 本文是《宠物问问 Agent 架构设计 v2》的实施规划，用于把 v2 设计落地为代码。当前仅完成规划，**未开始编码**；实施以 v2 文档（`docs/pet-ask-agent-architecture-v2.md`）为唯一行为契约，旧实现记录 `docs/ask-agent-development.md` 不作为 v2 依据。

## 1. 现状盘点（v1）

### 1.1 现有代码结构

| 层 | 目录 | 现状 |
|---|---|---|
| HTTP 接口 | `internal/httpapi/ask` | `handler.go` + `routes.go`：建会话、追问、reply、快照、事件轮询/流 |
| 业务核心 | `internal/app/ask` | 领域模型、状态机、调度、上下文、规则、宠物消歧、意图路由 |
| Provider 适配 | `internal/platform/ai` | OpenAI Responses API 与 Chat Completions 两套执行器，含错误分类与用量观测 |
| 数据库 | `migrations/000010~000014` | `ask_sessions/turns/runs/events/messages/session_pets/idempotency_keys` + row_version/租约字段 |

### 1.2 v1 已具备、可复用/演进的能力

| 能力 | 落点 | 复用方式 |
|---|---|---|
| 领域模型 Session/Turn/Run/Event/Message/IdempotencyRecord | `model.go` | 保留，按 v2 扩展字段（Attempt、TaskItem、Operation、来源版本、预算） |
| Run/Session 状态机 | `state.go` | 保留，补 `interrupted` 等终态与校验契约测试 |
| 事务持久化 + 幂等键 + 租约 + 崩溃恢复 | `repository.go` | 保留，按 v2 补唯一键、版本条件、删除标记、来源依赖 |
| 队列调度 + 心跳 + 有限重试 | `worker.go` | 保留，增加执行代次、检查点、四类预算、原子预留 |
| Provider 抽象 + 错误分类 + 用量观测 | `internal/platform/ai` | 演进为「决策 / 工具 / 摘要」三种调用用途 + 图片 + 计量归一化 |
| 宠物消歧、确定性风险规则、上下文组装、输出校验 | `pet_resolver.go` `rules.go` `context.go` `output.go` | 复用为工具/安全兜底，不再作为独立分类步骤 |
| 事件流 + 快照 + 幂等 | `handler.go` | 演进为「先持久化后发布」+ 分页恢复 |

### 1.3 v1 → v2 的核心差距

v1 是「两步式：意图分类 → 单次健康分析」，v2 是「单 Agent + Runtime 工具循环」。差距集中在：

| 维度 | v1 现状 | v2 目标 | 差距 |
|---|---|---|---|
| 决策模型 | 独立 IntentRouter 分类 + Execute 分析两步 | 首次业务决策统一处理健康/事实/闲聊/乱码/多宠物/多意图/追问/生图/能力不足 | 合并为单次决策，删除独立分类调用 |
| 工具循环 | 无 | 工具目录 + 批量校验 + 并行只读 + 依赖调度 + 指纹去重 | 全新 |
| 任务项 | 无 | task_item 清单，覆盖多宠物/多意图 | 全新 |
| 写入 | 无（模型只回文本） | Operation：冻结预览 → 逐项确认 → 独立执行 → 未知核实 | 全新（最复杂） |
| 长期记忆 | `fact.go` 简单查询 | 三类记忆 + 来源版本 + 派生任务 | 全新 |
| Skill | 无 | Skill 版本化 + BM25F 候选检索 | 全新 |
| 输出 | 单一 JSON + `safeDeltas` 假流式 | 动作先行 + 按对象/任务分组 + 短段发布 + 整版校验 | 重构 |
| 预算 | 仅 attempt 上限 | 工具/检索/模型/耗时四类预算 + 原子预留 | 全新 |
| 图片 | 不支持 | 文字 + 图片理解（生图明确延期） | 全新 |

## 2. 重构总体策略

### 2.1 演进原则

1. **以最小改动演进**：优先在现有 `internal/app/ask` 内新增文件/字段，规模足够大时才拆子包，不重排既有目录结构。
2. **先存后算**：数据库是唯一事实源；先落实访问与删除边界（T1/T2），联调阶段（T9）再做物理清理。
3. **旧代码渐进替换**：intent 路由、`safeDeltas` 假流式、`fact.go` 等在对应阶段被新能力替代，替换期内保留编译通过。
4. **遵守 `AGENTS.md`**：只改需求涉及文件，不批量格式化、不提交密钥、不碰 `web/dist`、`web/.taro`、构建产物。

### 2.2 目标模块落点（建议，实施时按规模取舍）

```text
internal/app/ask/
  （现有文件，按阶段演进）
  model.go state.go service.go executor.go worker.go repository.go
  context.go output.go rules.go pet_resolver.go dto.go
  （v2 新增，按规模决定文件 or 子包）
  skill.go        Skill 目录 + BM25F 候选检索
  tool.go         工具目录 + Runtime + Loop Guard + 指纹
  task.go         任务项清单与完成判定
  operation.go    Operation 冻结预览/确认/撤回/核实
  memory.go       三类长期记忆 + 来源版本 + 派生任务
  budget.go       四类预算 + 原子预留
internal/platform/ai/      Provider 抽象演进（三种调用用途 + 图片 + 计量）
internal/httpapi/ask/       HTTP 演进（图片上传、独立操作入口、分页恢复）
migrations/                000015 起新增 v2 表与字段
```

> 说明：具体是否拆子包在 P1 定领域 Schema 时一并决定，避免提前过度设计。

## 3. 分阶段实施计划（P0–P9）

> P0–P9 对应 v2 文档第 12.1 节的 T0–T9，验收对照第 12.3 节 A1–A20。每阶段完成即产生可编译、可测试的增量，不要求一次铺满全量能力。

### P0 基线验证（T0）

- **目标**：把「设计假设」换成「真实接口证据」，识别接入缺口。
- **内容**：
  - 记录候选 Provider 在选定模型下的真实组合能力：文字+图片、工具调用、结构化输出、有序流式、非流式、取消、拒绝/截断行为。
  - 核查现有业务事务、媒体（`internal/platform/storage`）、权限（`middleware`）、删除能力是否满足 11.3 基线。
  - 固定 12.2 六类前置证据：模型协议、隐私、用量、业务提交、健康语义、保留/资产。
- **产出**：`docs/` 下能力验证记录 + 缺口清单；未通过项标记为阻断对应依赖能力。

### P1 领域 Schema 与存储约束（T1）

- **目标**：固定 v2 全部领域 Schema、状态机与数据库约束。
- **内容**：
  - 扩展 `model.go`：Attempt、TaskItem、Operation、来源版本、派生任务、预算、引用契约；固定命令/结果/错误 Schema。
  - 新增迁移 `000015+`：task_items、operations、来源版本、memory 相关表；为现有表补 `input_revision`、`execution_epoch`、删除标记、来源依赖。
  - 落实 9.2 的事务、唯一键、版本条件；契约测试拒绝非法状态转移与错绑归属。
- **产出**：完整领域模型 + 迁移 + 状态机测试；决定子包拆分方案。

### P2 调度、预算与恢复基础（T2）

- **目标**：在 `worker.go`/`repository.go` 上补齐执行代次、检查点、四类预算、原子预留、先持久化后发布。
- **内容**：
  - 输入接收、会话唯一、Run 串行、执行代次、检查点、持久化任务、有界恢复。
  - 四类预算（工具/检索/模型/耗时）与原子预留；SessionSnapshot 与分页恢复。
  - 重复领取、崩溃、迟到返回不重置次数、不回开终态、不重复执行。
- **产出**：调度/预算/恢复的契约测试（对应 A1/A2/A16/A17）。

### P3 Provider、图片与计量适配（T3）

- **目标**：把 `internal/platform/ai` 从「两套分析执行器」演进为「三种调用用途 + 图片 + 计量归一化」。
- **内容**：
  - 三种调用用途（首次决策 / 工具循环 / 按需摘要）；固定 Profile、能力、可选参数。
  - 结构化输出、流式与允许的非流式降级、取消、用量归一化、调用预留与幂等结算。
  - 图片校验与处理上限；**不注册生图能力**。组合能力与隐私通过后才启用对应适配器。
- **产出**：Provider 抽象 + 图片 + 计量（对应 A6/A8/A17 的 Provider 部分）。

### P4 工具目录与业务读取（T4）

- **目标**：落地 Skill + 工具目录 + 工具 Runtime 与 Loop Guard。
- **内容**：
  - `skill.go`：Skill 版本化 + BM25F 候选检索 + 一次兜底。
  - `tool.go`：工具目录版本发布；宠物消歧、档案、记录、精确聚合、旧聊天引用、来源补取。
  - 整批校验、独立只读并行、局部失败、来源集合核验、跨 Run 复用；读取错误与无记录始终分开。
- **产出**：工具目录 + 只读工具 + 契约测试（对应 A4/A5/A7 的读取部分）。

### P5 核心问答与发布（T5）

- **目标**：单 Agent 决策循环 + 结构化流式发布。
- **内容**：
  - 首次业务决策（合并原 intent 路由与 analysis）、任务项覆盖、追问与有限答复。
  - 上下文组装、32/16 摘要、来源引用、按对象分组与短段发布；不保存 CoT。
  - 安全规则与注入评测；整份答复最终校验、失效折叠、正文后不自动重发。
- **产出**：核心问答闭环（对应 A3/A7/A8/A16 的问答部分）；`intent.go`/`safeDeltas` 在此阶段被替代。

### P6 确认写入与独立核实（T6）

- **目标**：落地 Operation 全生命周期（v2 第 10 节），这是本轮最复杂的增量。
- **内容**：
  - `operation.go`：冻结预览、逐项确认/放弃、领取前撤回、单项事务、依赖调度、未知核实。
  - 15 分钟预览、5 分钟执行、24 小时/24 次核实（5 秒翻倍、最长 2 小时、单次 10 秒）。
  - 与真实回执、来源版本、记忆更新一致提交；**不提供人工核实入口**（附录 A 非一期）。
- **产出**：Operation 状态机 + 确认/撤回/核实（对应 A9–A14）。

### P7 长期记忆及回源（T7）

- **目标**：三类长期记忆 + 来源版本失效。
- **内容**：
  - `memory.go`：所有允许写入/更正/删除路径推进来源版本与派生任务。
  - 三类记忆、完整原文与模板校验、检索与时效、引用及来源变化失效。
  - 派生失败仍查原记录，更新不再确认；不引入向量或额外审核模型。
- **产出**：记忆提取与后续问答分别验收（对应 A14/A15）。

### P8 页面恢复与操作入口（T8）

- **目标**：接通前端交互所需的全部接口。
- **内容**：
  - 文字/图片输入、草稿保留、追问、回答版本、最近三次只读历史、事件恢复、逐项预览、独立操作入口。
  - 最小回执、撤回、状态刷新、记忆整理状态按权限展示；后台切页不停止服务端任务。
  - 前端 `web/src` 相应页面/服务接入（只读历史、预览确认、独立入口）。
- **产出**：可用的页面恢复与操作入口（对应 A2/A6/A9/A19 的交互部分）。

### P9 清理、联调与发布验证（T9）

- **目标**：跑通验收并交付。
- **内容**：
  - 到期与主动删除、主存/备份清理、恢复前应用删除标记、供应商处理边界、用量对账。
  - 运行 A1–A20 核心场景 + 真实模型固定评测。
  - 数据迁移、配置启用、回滚步骤；回滚不复活已失效内容、不重做写入、不重置授权。
- **产出**：验收报告 + 上线/回滚手册。

## 4. 关键风险与约束

| 风险/约束 | 应对 |
|---|---|
| 真实 Provider 组合能力未验证（文字+图片+工具+结构输出） | P0 先取证，未通过项阻断依赖能力接入 |
| v2 字段/Schema/配置大量「待定稿」 | 在对应阶段固定（P1 定 Schema、P3 定 Profile、P4 定工具目录、P6 定 Operation 配置），不无限扩散 |
| Operation 与长期记忆体量最大 | 严格按 P6/P7 顺序，先存后算，逐项契约测试 |
| 旧聊天「最近三次只读」与来源版本失效边界复杂 | 依赖 P1 的来源版本与删除标记，避免后补过滤 |
| 前端与后端同步改造 | P8 统一接入，前端仅对接新接口，不改历史数据格式 |

## 5. 已确认决策（2026-09-17）

| 决策点 | 结论 |
|---|---|
| Provider/模型与 Key | 沿用现有 API Key（`deepseek-chat` / tokenflux.dev），生图模型的 Key 后续补充（生图一期已延期，不阻塞） |
| 子包拆分粒度 | **同包多文件**：`skill.go` / `tool.go` / `task.go` / `operation.go` / `memory.go` / `budget.go` 等，不拆子包 |
| 实施顺序 | **按 P0–P9 全量推进** |
| 旧接口兼容 | **允许整体替换**，按 v2 文档需要改，不保留 v1 接口兼容 |
