# 背景知识库（RAG）

本目录是宠物问问的背景知识库层：已审核、可版本化、可撤回的参考资料。
知识只影响回答内容，不改变权限、家庭隔离、写入确认、风险升级条件和工具调用权限。

## 发布方式（已确认）

一期使用仓库文件发布，不建数据库发布表，也不做管理后台：

```text
写条目文件 -> 本地跑测试 -> 提升 manifest 版本号 -> 提交 -> 部署后生效
```

选择这个方式的原因：内容量小、改动需要审核、可以完整留痕，改动随代码一起 review。
代价是撤回要重新部署，非研发人员改不了内容。

**后续触发条件**：当出现「需要不改代码即时上架/下架一条知识」的真实需求时，
再建数据库知识表与审核状态机（草稿 / 校验 / 安全审核 / 检索测试 / 发布 / 撤回）。
在此之前不提前建设。

## 目录与文件

```text
internal/platform/knowledge/
  corpus/manifest.yaml   知识目录版本清单
  corpus/*.md            知识条目（每个 .md 都是一条条目，不能放说明文档）
  document.go            条目契约与校验
  parse.go               条目书写格式解析
  index.go               BM25F 索引（与工具目录索引分开）
  catalog.go             版本目录与内嵌加载
  retriever.go           只读检索与红旗条目强制保留
```

`corpus/` 下每个 `.md` 都会在服务启动时解析；任何一条格式非法都会让服务启动失败，
错误信息带文件路径。这是刻意的：宁可启动失败，也不让未审核或半成品知识进入 Run。

## 新增一条知识

1. 在 `corpus/` 新建 `<topic>-<species>.md`，按下面格式书写。
2. 跑 `go test ./internal/platform/knowledge/...`，确认解析与检索通过。
3. 提升 `corpus/manifest.yaml` 的 `version`（格式 `YYYY-MM-DD.vN`，同一天多次改动递增 `vN`）。
4. 提交，随服务部署生效。

```text
主题：猫咪呕吐
适用宠物：猫
原始来源：某宠物医院科普文章
来源日期：2026-09-20
审核日期：2026-10-05
风险等级：yellow

正文：
...
```

必填：主题、适用宠物、正文。其余字段不写就保持为空，解析器不会编造。

可选字段：生命周期、主题词、关键词、症状、就诊等级、有效期至、知识版本、状态、
支持、不支持、观察项、升级条件（别名「就医条件」）、禁忌、相关主题。

书写要点：

- 一条条目只解决一个主要问题（一个物种、一个主题、一个主要结论）。
- 红旗症状和就医条件优先写成独立的「升级条件」字段；没有单独写时，
  正文里命中红旗表短语的段落会被自动抽出来，但这是安全网，不如显式书写可靠。
- 红旗短语表在 `internal/platform/safety/redflags.go`，人工审核版见 `docs/red-flags.md`。

## 引用标识

`document_id` 与 `chunk_id` 由加载器生成，不需要手写：

```text
document_id = pet_health.<主题码>.<物种码>        例如 pet_health.vomiting.cat
chunk_id    = <document_id>.<文件名后缀>          例如 pet_health.vomiting.cat.observation
```

后缀取自条目文件名去掉主题码与物种码后剩下的部分（`cat-vomiting-observation.md`
→ `observation`），这样同一主题下新增条目不会改写已有条目的 `reference_id`。
文件名全部被去掉时才退回文档内顺序编号。已经发布的 `reference_id` 一旦被历史回答引用，
不要改文件名；新增内容请新建文件。

## 生命周期分段

段位取自 2026-10-06 整理稿，代码在 `agestage.go`，由 Runtime 依据宠物档案的生日
（缺失时退回档案年龄）计算，模型不参与。

```text
猫咪：幼猫期 young 0-11 月 / 青年期 adult 12-83 月 / 熟龄期 mature 84-119 月 / 老年期 senior 120 月起
狗狗：幼犬期 young 0 至幼年期结束 / 青年期 adult 到 35 月 / 壮年期 mature 36-83 月 / 老年期 senior 84 月起
```

犬的幼年期结束时间按成年体重分档：5 公斤及以下约 9 个月，5-20 公斤约 12 个月，
20-40 公斤约 18 个月，40 公斤及以上约 21 个月。体重暂未入库，未知时按中型犬的
12 个月处理；等档案能读到体重后再按实际体型判断。年龄无法计算时按未确认处理，
不做生命周期过滤。

## 修改与撤回

- 改正文：直接改文件并提升 `manifest.version`。历史 Run 仍然记着当时的
  `knowledge_version`，不会被改写。
- 撤回：把条目改成 `状态：withdrawn`（或删除文件）并提升版本号，部署后新 Run 不再使用。
  不要删除后复用同一个 `chunk_id` 给新内容，否则历史引用的指向会变。
- 过期：写 `有效期至：YYYY-MM-DD`，到期后自动被硬过滤，不需要改状态。

## Runtime 侧约定

- 模型只能提出 `search_pet_knowledge` 检索请求，不能指定 `document_id` 绕过检索，
  也拿不到草稿和已撤回条目；工具参数只有 `query`、`pet_id`、`limit`。
- 物种与生命周期由 Runtime 从宠物档案（`pets.species`、生日/年龄）读取后注入，
  模型不能自己填写物种或生命周期；
  `pet_id` 必须在本次会话已授权宠物范围内，否则整项调用被拒绝。会话只有一只宠物时
  可以不带 `pet_id`；多只宠物又没指定时物种保持未确认，不做物种过滤，也不做替代。
- 档案里的物种写法由 `NormalizeSpecies` 归一化（`猫`/`cat` → `cat`），无法识别时
  按未确认处理，不用品种猜测。
- 最终回答只能引用本次真实注入的 `reference_id`（`source_type=pet_knowledge`），
  伪造的引用会在来源校验阶段被丢弃。
- 知识未命中（`retrieval_status=no_match`）与检索故障（工具项 error）严格区分。
